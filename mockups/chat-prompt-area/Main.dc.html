I created issue #664: https://github.com/gic-developer-sandbox/primepaw/issues/664

I labelled it enhancement. I didn't read the body back or link it to other issues.

I found why this happens. In task-detail-view.tsx, local cards already render markdown. Synced cards (GitHub issues and Jira) show their description as plain text. A code comment says that's because tracker text is untrusted. Both sources are markdown, so headings, lists and links show up raw.

The plain-text rule is about untrusted HTML, and the app's markdown renderer is already safe against that. It builds a virtual DOM and drops raw HTML, and markdown-preview.tsx warns against adding rehype-raw. So the issue asks to render markdown with the same renderer as the rest of the app, with raw HTML never enabled.

The issue also covers:

  • Links: only safe schemes (no javascript: links), opened in a new tab.
  • Images: they should not load automatically, because remote images in an issue body would make the browser fetch from third-party hosts as soon as the card opens.
  • Layout: long descriptions and wide tables are contained.
  • Task lists: they render read-only.

The RUM SDK is now initialised in app/root.tsx behind the DATADOG_RUM_ENABLED flag, with the client token read from the runtime config rather than the bundle. Session replay is off by default.

Still running: the e2e suite against staging to confirm no CSP violations from browser-intake-datadoghq.com. I'll open the PR once it's green.
